# External-input ablations: Dadras and Rossler

Run from `ALRNN-DSR-extended/alrnn_python` on the Linux server:

```bash
bash run_dadras_cphi_without_phi1.sh 0 1 2 3
bash run_rossler_cphi_shifted_split.sh 2 3
```

These are separate experiments. When both scripts run at the same time, give
them disjoint GPU lists. They do not coordinate with other scripts or users.
IDs refer to the CUDA devices visible to the selected Python environment.
With no arguments, `$GPU_ID` is used, defaulting to `0`.

Both scripts activate `$ROOT_DIR/DynaMix-python-b-tipping/venv/bin/activate`;
`ROOT_DIR` defaults to `$HOME`. The existing `TRAINING_DATA_ROOT`,
`BIFURCATION_DIR`, and `PYTHON_BIN` environment overrides are supported.
Each regime's trajectory folder may contain the four data files directly or
inside `values_8/`. Precomputed `windows/` datasets are not used.

## Models and parameter subsets

Each script trains four variants, without an additive-only baseline:

| Folder | Additional terms (`--phi-terms`) |
| --- | --- |
| `diagonal` | `(D_phi @ phi[t]) * z[t]` |
| `diagonal_relu` | `(D_relu_phi @ phi[t]) * relu_P(z[t])` |
| `shifted_relu` | `V_phi @ relu_P(z[t] + Q_phi @ phi[t])` |
| `additive_diagonal` | `C @ phi[t] + (D_phi @ phi[t]) * z[t]` |

The standard AL-RNN recurrence remains in every variant. Only the listed
external terms are enabled. Each variant trains three independent models:

- Dadras: all seven values except `phi=+1`, four negative values, three positive
  values except `phi=+1`. Its bifurcation comparison uses `e=4.9..6.2`.
- Rossler: all eight values, three lower negative values (without
  `phi=-0.1428571`), and five upper values (including `phi=-0.1428571`). That
  value keeps its original negative sign as model input. Its bifurcation
  comparison uses `a=0.05..0.35`.

Values are read from metadata and checked against the trajectory constants.
Every model uses the existing balanced phi sampling. Training restrictions do
not change the trainer's final evaluation: it still tests all available phi
values, including Dadras `phi=+1`. Only the bifurcation range is truncated.

Hyperparameters are M=200, P=20, 750 epochs, batch size 80, 100 batches per
epoch, and four CPU threads **per active pipeline**, not four in total. Change
these settings near the top of each shell script. Other trainer defaults remain
unchanged.

## Scheduling, progress, and adding GPUs

One GPU handles one variant's three trainings sequentially, followed by its
bifurcation comparison (three trained models and ground truth, 320 parameters,
component `z`). A free GPU then takes the next pending variant. Thus two GPUs
run two variants at once, with the other two waiting. There are 12 trainings
and four bifurcation comparisons per script.

At startup the runner prints a path to its live `gpu_ids.json`, initially e.g.
`[2, 3]`. Edit that file while the script runs to add a newly available GPU:

```json
[2, 3, 1]
```

The runner polls it every two seconds. The added GPU takes a pending variant;
already running pipelines are not migrated or accelerated. Only add GPUs you
are allowed to use. A maximum of four distinct IDs is accepted. Removing an ID
prevents new pipelines there but lets its current pipeline finish. Invalid or
partially written JSON is ignored until it becomes valid again.

Stage changes appear in the terminal. Training progress bars and metrics go
into one log per variant; the startup output includes a `tail -f .../*.log`
command. A failed stage stops that variant, but the others continue. The final
exit code is nonzero if any variant failed. Ctrl+C/SIGTERM terminates running
child process groups on Linux; completed models remain on disk. For overnight
runs, keep the script in `screen` or `tmux` and detach instead of exiting it.

## Outputs and checks

Each invocation has its own timestamped directory, so it does not overwrite
previous experiments:

```text
runs/term_ablations/<regime>/<timestamp>_m200_p20/
  gpu_ids.json
  plan.json
  summary.json
  logs/<variant>.log
  <variant>/{all,negative,positive}/
bifurcation_diagrams/term_ablations/<regime>/<timestamp>_m200_p20/
  <variant>/bifurcation_compare.png
  <variant>/bifurcation_cache.npz
```

The runner calls this repository's local bifurcation adapter so the new terms
are loaded correctly. Ground truth is generated by the existing backend.

To validate paths, subsets, and all commands without CUDA or training:

```bash
DRY_RUN=1 bash run_dadras_cphi_without_phi1.sh 0 1
DRY_RUN=1 bash run_rossler_cphi_shifted_split.sh 0 1
python -m unittest test_term_ablations -v
```

## Combined additive + shifted-ReLU experiment

```bash
bash run_dadras_rossler_cphi_shifted_relu.sh 0 1 2 3 4 5
```

This additional script trains only `--phi-terms additive shifted-relu`: the
standard AL-RNN plus `C @ phi` and `V_phi @ relu_P(z + Q_phi @ phi)`. Neither
diagonal coupling term is enabled. The four-variant scripts above are unchanged.

It creates six independent training jobs: Dadras and Rossler, each on all,
negative, and positive values. The existing Dadras exclusion of phi=+1 and
Rossler's shifted 3/5 split are retained. M=200, P=20, 750 epochs, batch size 80,
100 batches per epoch, and four CPU threads per active training are the defaults.
The same venv activation and path environment overrides are used.

One to six GPU IDs can be supplied. Each GPU runs one training at a time and
takes the next pending job when it finishes. The first two jobs are Dadras all
and Rossler all. Unlike the four-variant experiment, different subsets of the
same system can train concurrently. After all six trainings finish, two
bifurcation jobs compare each system's three models with ground truth. A
system's comparison is skipped if one of its trainings failed; the other
system can still complete. Existing bifurcation ranges and 320 parameter
values are retained.

With six GPUs all six trainings can run simultaneously (24 CPU threads in
total at the default four threads per training). The older four-variant
scripts keep their four-GPU limit.

```text
runs/term_ablations/<regime>/cphi_shifted_relu/<timestamp>_m200_p20/
  {all,negative,positive}/
bifurcation_diagrams/term_ablations/<regime>/cphi_shifted_relu/<timestamp>_m200_p20/
  bifurcation_compare.png
  bifurcation_cache.npz
runs/term_ablations/_queues/cphi_shifted_relu/<timestamp>_m200_p20/
  plan.json
  gpu_ids.json
  summary.json
  logs/{dadras,rossler}_{all,negative,positive,bifurcation}.log
```

Progress commands and per-system output paths are printed at startup. Shared
logs, plan, summary and the live GPU list are in `_queues`, because one queue
controls both systems. The live list accepts up to six GPU IDs, including
updates while jobs are pending. Existing output folders are not moved.
Do not share GPUs with another running experiment unless this is intentional.
A dry run prints all eight commands without requiring CUDA:

```bash
DRY_RUN=1 bash run_dadras_rossler_cphi_shifted_relu.sh 0 1
python -m unittest test_term_ablations test_cphi_shifted_regimes -v
```
